# 看小说 / 看漫画（aurabot-novel）

Aurabot 扩展模块：**读小说、看漫画，学书里角色说话做事**。支持 `.txt` / `.docx` / `.epub` / `.pdf`，
以及**一页一张图的漫画 PDF**（比如《妄想学生会》那种扫描版，没文字层也能看）。

> 大肥鱼（Aurabot 里的 QQ 伙伴）装了它之后，会把书读进书架、拆出人物卡，
> 然后学其中某个角色的性格、说话和做事方式 —— 不是扮演，也不会变成另一个人。
>
> 漫画走的是**视觉模型**：她是一页页真的在看图，不是 OCR 硬认字。

## 安装

**从 Release 下 zip，解压到 Aurabot 的扩展目录**：

```powershell
Expand-Archive .\aurabot-novel-1.2.1.zip -DestinationPath "$env:USERPROFILE\.dsh\plugins-data\aurabot\modules" -Force
```

解压后应该是 `...\modules\novel\index.mjs`。几秒内面板「扩展」页会出现「看小说 / 漫画」，显示「已启动」就好了。

- 升级：把 `modules\novel` 整个删掉，再解压新的。书架数据在 `modules-data\novel`，不会丢。
- 卸载：删掉 `modules\novel`；想连数据一起清空，再删 `modules-data\novel`。

## 怎么把书给她

三种都行：

1. **直接发 QQ 文件**：主人在私聊或群里发文件，她自动收下并开始读 / 看（设置里可以关）。
   注意 QQ 的文件通道很慢（实测 ~60KB/s），**大文件建议走下面第 2 种**：超过「单本最大 MB」的文件她会直接拒收并说清楚，
   不会像以前那样卡两分钟再报一串看不懂的 OneBot 错误。
2. **放进书架文件夹**（大文件推荐）：
   `%USERPROFILE%\.dsh\plugins-data\aurabot\modules-data\novel\shelf\`
   放进去后 5 分钟内自动收书，急的话发 `/小说 刷新`（= `/小说 书架`）立刻收。
3. **导入路径 / 网址**：`/小说 导入 D:\books\某本书.epub`、`/小说 导入 https://example.com/novel.txt`

> 收 QQ 文件的两个坑（2026-10-29 实测，73MB 的 PDF 卡死）：
> ① 下载直链必须带 `Range: bytes=0-`，否则 QQ 那边要准备好整个文件才回头，25 秒都拿不到响应头；
> ② 通道只有几十 KB/s，70MB 要下 20 分钟。现在改成流式下载（边下边按上限截断、总预算可配、会报进度），
> 并且**先用消息段里的 `file_size` 判断**：超上限直接告诉她「调大上限」或「放书架」，不浪费那两分钟。

支持的格式：

| 格式 | 说明 |
|---|---|
| `.txt` / `.md` | UTF-8、GBK / GB18030、UTF-16 都认；网页另存的 HTML 也能扒正文 |
| `.docx` | 按 Word 正文顺序抽，图片和批注不读 |
| `.epub` | 按书里的目录（OPF spine）顺序读，目录页、封面、注音不会混进正文；自动用书里写的书名 |
| `.pdf`（有文字层） | 抽正文，见下面「PDF 的注意」 |
| `.pdf`（一页一张图） | 当漫画看：抽出每页的原始图片，交给视觉模型一页页看，见「漫画 PDF」 |

## 漫画 PDF（一页一张图）

扫描版漫画通常长这样：156 页，每页一张 1279×1920 的 JPEG，PDF 里**一个字体都没有**。
这种书抽不出正文，以前只能回「扫描版读不了」；现在会：

1. **本地拆页**：不装渲染器、不截图，直接按 PDF 页树找到每页最大的那张图，记下它在文件里的偏移
   （70MB 的书扫一遍约几十毫秒，只读目录结构）。JPEG 原样拿出来，Flate 压缩的图转成 PNG。
2. **认人**：先看开头 3 页，列一份人物名册（名字 / 长相 / 身份）。没有名字的角色用稳定的外貌称呼
   （比如「黑长直学生会长」），后面每段都带着这份名册，避免同一个人每段换个叫法。
3. **分段看**：每段默认 6 页（设置可调 2~10 页），把图片直接交给视觉模型，
   拆出剧情、人物的性格 / 说话方式 / 做事风格、画面上的原话台词（**繁体就保留繁体**）。
   156 页的长篇按「每本最多读几段」均匀抽样（首段、中间、结尾都会看），不是每页都烧一遍。
4. **合并**：和读小说用同一套逻辑整理人物卡，所以 `/小说 角色`、`/小说 卡 名字`、`/小说 学 名字`
   对漫画一样能用。

她也能在聊天里**翻页看**：说「漫画第 5 页写了什么」「第 154 页那句台词是什么」，
她会用 `novel_page` 工具只把那一页交给视觉模型，不会整本重看。

> 前提：当前模型要能看图。面板「模型」里选 `DeepSeek-V4.1-Flash`（能看到「视觉」标记），
> 或者把「视觉能力」手动设成 `on`。看不了图时她会直接说清楚，不会假装读过。

## PDF 的注意

PDF 是最容易出问题的一种，先看清楚：

- **加密 PDF 读不了**：设了打开密码或权限保护的，需要先解开。
- **特殊字体排版的 PDF 可能抽不出来**：少数 PDF 用的是子集字体、又没带文字映射表（ToUnicode），抽出来会是乱码 —— 她也会明说，建议转成 txt / epub。
- 正文里的**换行会按段落拼回去**（PDF 的排版折行不是真段落），表格和公式可能会挤在一起，这不影响学角色，但别指望它排版精确。
- **既是图片又是文字**（比如文字层只有页码）的 PDF，会优先当小说读；正则读不出多少字时才转成漫画模式。

## 命令（只有主人能用）

`/小说` 和 `/漫画` 是同一个命令，下面这些都能用：

| 命令 | 作用 |
|---|---|
| `/小说` 或 `/小说 帮助` | 看说明 |
| `/小说 书架` | 有哪些书 / 漫画、读到哪了 |
| `/小说 读 书名` | 开始 / 接着读（漫画就是「接着看」） |
| `/小说 进度` | 小说读到第几段 / 漫画看到第几页 |
| `/小说 停读` | 正在读的长篇先停下 |
| `/小说 角色` | 每本书里拆出了哪些人物 |
| `/小说 卡 名字` | 看某个人的详细人物卡 |
| `/小说 学 名字` | 学他说话做事（`/小说学名字` 也行） |
| `/小说 停` | 不学了，做回自己 |
| `/小说 删 书名` | 从书架删掉这本书（漫画只删索引，不动你 D 盘的原文件） |

她自己也有一组工具：`novel_shelf`、`novel_recap`、`novel_read`、`novel_page`、`novel_learn`。
所以你在聊天里说「你在看什么书」「第 20 页那个人说了啥」「学学沈七说话」，她会自己用。

## 设置（面板「扩展」→「看小说 / 漫画」）

- **学角色（总开关）**：关掉就不往人格里加料，人物卡还在。
- **读完自动学主角**：默认开。读完一本自动学书里最主要的角色；想换人发 `/小说 学 名字`。
- **学的力度**：轻 / 中 / 重。越重，带的口头禅和腔调越多，占用提示词也越多。
- **每次读多少字** / **每本书最多读几段**：长篇会均匀抽样（首尾都会读），不是每段都读。
  默认 4500 字 × 30 段 ≈ 13.5 万字；想更准就调大，想省钱就调小。漫画的「段」= 几页。
- **看漫画时真的看图**：关掉只收进书架不读（省额度）。
- **每次看几页漫画**：默认 6 页。一次塞太多图模型会看漏，太少又慢。
- **自动收书** / **主人发书自动读**：上面两种收书方式。
- **单本最大 MB**：超过就不收（QQ 文件会秒拒并提示，书架里的会记一条 warn）。默认 20MB。
- **收 QQ 文件最多等几秒**：QQ 文件通道慢，小文件够用；默认 480 秒（8 分钟）。大文件建议直接放书架文件夹。
- **读书 / 看漫画时的额外要求**：会附在每次分析的提示词里，比如「重点学女性角色」「多收集口头禅」。

## 数据放在哪

`%USERPROFILE%\.dsh\plugins-data\aurabot\modules-data\novel\`

- `library.json`：书架、人物卡、现在学的是谁（每本书还记着格式、页数、原 PDF 在哪）
- `books/<id>.txt`：小说导入时抽出来的正文（已经转成纯文本，原文件删了也能重读）
- `books/<id>.pdf`：从 QQ / 网址收来的漫画才会复制一份；**从书架文件夹 / 本地路径导入的只记原路径**，
  不占双份空间（原文件被移走 / 删掉时会提示重新导入）
- `index/<id>.json`：漫画的页索引（每页图片在 PDF 里的位置、尺寸），很小；PDF 换过了会自动重建
- `notes/<id>.json`：分段阅读 / 看漫画的笔记（看到一半停下，下次接着看；里面还有那份人物名册）
- `shelf/`：你往里面丢书的文件夹

22 本漫画、每本 70~90MB，全放书架也只多出几百 KB 的索引，不会把书复制一遍。

删模块文件夹不会删这些数据；想彻底清空就删 `modules-data\novel`。

## 注意

- 读一本书 / 看一本漫画要调模型很多次（每段一次 + 最后合并一次），会花时间，也会消耗模型额度。
  漫画比小说更费：一段 6 页图，一次请求就是几张高清图。默认「每本最多读 30 段」是有意压着的。
- 模型偶尔会返回看不懂的内容：那一段会跳过，最后提示「有几段没读成」；失败太多会报错，重新发 `/小说 读 书名` 会重试失败的段。
  漫画那段如果只是先写了一段分析才给 JSON，会自动再要一次纯 JSON。
- 看漫画的视觉请求关掉了模型的思考过程（`reasoningEffort: 'off'`）：实测 6 页图时，
  思考 token 会把输出额度吃光、返回一个空字符串；关掉后既稳定又省额度。
- 漫画里没有写名字的角色，人物卡用外貌称呼；她认得这部作品时会用通行译名，但拿不准宁可写长相。
- 她学的是**风格**，不是替你复述原著；人物卡里的「原话」只用来抓语气。
- 模块重新加载时，正在读的书会停住（标记为读了一半），发 `/小说 读 书名` 从没读的段接着来。
- 大文件慢一点：一份 20MB 的 PDF 抽文字要几百毫秒到一两秒（不联网、不装依赖，纯本地解）。
